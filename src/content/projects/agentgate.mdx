## Problem

AI agents increasingly act through MCP servers: CRM lookups, ticketing, databases. That opens two quiet failure modes:

- A server that is trusted today can change its tool descriptions tomorrow. This is called a "rug pull", and the agent will happily follow the new instructions.
- A prompt-injected agent can start calling tools it was never meant to use.

Most teams have no inventory of which agent can call which tool, let alone a way to stop it.

## What I'm building

AgentGate puts a lifecycle around that access. Agents are treated as non-human identities, and every tool they can reach has been reviewed, pinned and granted.

## How it's put together

Four services, each owning its own data:

- **Registry**: MCP servers, pinned tool manifests, agent identities, drift detection.
- **Review**: risk scans, four-eyes approval, grants (agent × server × tools).
- **Gateway**: a YARP proxy that answers `tools/list` from the pinned manifest and checks grants on `tools/call`.
- **Hub**: a read model built only from events. It shows inventory, who can call what, an audit timeline and live activity.

Services talk through events on RabbitMQ with a transactional outbox and inbox. There is exactly one synchronous gRPC call, used where a check has to be authoritative at the moment a state changes. Agents authenticate to Keycloak with client credentials.

## Hard parts

- **Where to be synchronous.** Events everywhere is clean until a decision has to be authoritative right now. I kept exactly one gRPC call for that case and left everything else asynchronous.
- **Making drift cheap to detect.** Pinning a hash of the approved manifest turns "did this server change?" into a comparison instead of a diff.
- **Rules enforced, not documented.** Architecture tests (NetArchTest) fail the build if the domain kernel picks up a framework dependency. Decisions like "one database engine and one endpoint style across services" are written down as ADRs.

## Where it stands

The repo foundation (building blocks, Aspire host, architecture tests, CI) and the enforcing gateway with a demo MCP server and agent are done. The registry with manifest pinning and drift-triggered quarantine is in progress. Then: review and grants, the Hub with a React console, and anomaly-based auto-suspend.
